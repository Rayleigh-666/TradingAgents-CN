## 二、P1 落地实测（含本轮补修）

### P1-1 `parse_holdings` 弱形态兜底造幻影标的

原文修法原文照录：

> **修法**：两轮定位——第一轮只认强形态（6 位数字、带点号/交易所后缀、显式 `.HK`）；第二轮兜底对弱形态 token 要求「剩余 token 能解释为权重/成本」**或「本地库查得到」**，否则 warning 跳过。

**实现只做了前半个「或」条件。** 我实测复现了由此残留的两条路径：

| 输入 | 修复前 | 上一次修复后 | 本轮补修后 |
|---|---|---|---|
| `not json at all` | 幻影美股 `NOT`，无告警 | ✅ 跳过 + warning | ✅ 跳过 + warning |
| `aa,600519,30` | 整行丢弃，归因「权重 600519 非法」 | ✅ `600519` / 30%，`aa` 降为名称 | ✅ 不变 |
| `600519,-30` | `name='-30'`、weight=None、**无告警** | ✅ 跳过 +「权重 -30 非法」 | ✅ 不变 |
| `腾讯控股,00700,30` | 整行丢弃 | ✅ `00700` 港股 / 30% | ✅ 不变 |
| `600519,30,1500,1600` | `1600` 静默丢弃 | ✅ warning「多余数值 token（1600）」 | ✅ 不变 |
| `aa,30` | — | ❌ **幻影美股 `AA` / 30%** | ✅ 跳过 + warning |
| `30, 25` | — | ❌ **幻影港股 `00030` / 25%** | ✅ 跳过 + warning |
| `AAPL,30` | — | ✅ `AAPL` / 30%（保留） | ✅ 不变 |
| `600519`（无权重） | — | ✅ weight=None | ✅ 不变 |

**补修做法**（`core/agents/adapters/portfolio_analyst_v2.py`）：新增 `_symbol_exists_locally(market, symbol)`，弱形态候选在「数字支撑」之外**还必须存在于 `basic_info_collection(market)`**；强形态（6 位数字 / 含点号 / 含连字符）**不查库**，避免误杀尚未预热的合法代码。

取值的三态设计（这是本轮唯一新增的 DB 依赖，刻意收得很窄）：

| 返回 | 含义 | 调用方行为 |
|---|---|---|
| `True` | 库内命中 | 采纳该 token 为代码 |
| `False` | 集合可查但未命中 | 跳过该候选（确定的「不存在」） |
| `None` | 无法判定（集合为空 / 查询异常） | **fail-open**，保持既有行为 |

实测证据（本机库：cn 11149 / hk 674 / us 517）：`00700` ✅ 在库、`AAPL` ✅ 在库、`00030` ❌ 不在库、`AA` ❌ 不在库、`NOT` ❌ 不在库。

### P1-2 一行误解析一票否决整包有效前沿

原文修法：

> **修法**：区分「真实非 A 股持仓」与「弱形态兜底命中的可疑标的」——仅前者触发 cn_only 文案；后者剔除该行 + warning，其余 A 股照常算 EF。

**最终实现不是这个分层**，而是**整体移除 `market_type != "cn"` 的整包降级**：任何非 A 股标的都逐只跳过 + 各自 warning，代码里不再有「可疑标的」这一概念，也不再出现「检测到非 A 股标的」这句文案。原文建议的分层会引入一个并不需要的中间态（见 C9）。

实测三组（`compute_portfolio_facts`，`lookback=252`）：

| 输入 | cn_only | 有效前沿 | 告警 |
|---|---|---|---|
| 3 只 A 股 + 一行 `not json at all` | `False` | ✅ 保留（3 只） | 仅「第 4 行无法识别为证券代码」 |
| 3 只 A 股 + 1 只港股 `00700` | `True` | ✅ 保留（3 只 A 股照算） | 「标的 00700 属于 hk 市场…该项已跳过」+ 其余照常 |
| 纯港股 2 只 | `True` | ❌ 缺失 | 逐只跳过 × 2 + 「**可用 A 股标的不足 2 只**，无法计算组合有效前沿。」 |

即：**一行垃圾 / 一只港股都不会再让 A 股部分的有效前沿消失**，纯非 A 股组合则给出可解释的「不足 2 只」而不是错误的归因。

## 五、对原文自身的更正（本节是「更正后报告」的核心）

> 说明：原文主动认领了它自己第七轮的两处归因错误（哨兵 `"MARKET"`、`guess_market` 补丁），这一点值得肯定。下面 8 条是**本轮新发现**的原文不准确之处。

### C1（重要）P1-1 修法只落地了一半，原文未标出残留
原文修法写的是「『剩余 token 能解释为权重/成本』**或「本地库查得到」**」——是一个**或**条件，两个分支都不该缺。实现只做了前者，于是 `aa,30`、`30, 25` 两条幻影路径存活。
原文在「四、修改方案分项结论」里给 `parse_holdings` 弱形态兜底判的是「有缺陷（P1）」，但**没有说明这个缺陷在修复后是否闭环、以及以什么判据闭环**，导致「修了但没修干净」无法被发现。本轮已补修并给出可复跑的判据（见第二节表格）。

### C2 P2-4「展示值自相矛盾」的表述与实际不符
原文说「`weights_used` 塌缩：实测 `{'600519': 40.0}`，而 HHI=0.52 隐含 60/40，**展示值自相矛盾**」。
实测更正：`weights_used` **从未进入报告正文**——报告正文只渲染「逐行持仓明细 + 按行计算的 topN/HHI」，本身是自洽的（`600519,30/600519,20/000001,30` → 明细 3 行、top1 37.50%、HHI 0.3438、原始权重合计 80%）。
因此准确表述应为：**机器可读字段 `weights_used` 的塌缩与其声明口径不符**（是字段级缺陷，不是「用户看到的报告自相矛盾」）。这个区别决定修复优先级——按原文措辞会误判为用户可见的严重问题。

### C3 P2-2「桥接后删平行实现」不可照做
legacy `Toolkit.get_stock_sentiment_unified` **仍有 3 处生产调用方**：
- `core/workflow/builder.py:898`
- `tradingagents/graph/trading_graph.py:1141`
- `tradingagents/agents/analysts/social_media_analyst.py:118`

原文只说「news 工具已桥接，情绪没有」，没提调用方，按字面「删」会打断这 3 处。实际落地为**桥接**（保留入口、删除平行逻辑），与 news 工具的处理保持一致。

### C4 P2-1「一行改动」只适用于两处中的一处
原文把 `stock_sentiment.py:424,451` 与 `agent_utils.py:1478` 并列，给出「传归一化后的 `_symbol`，一行改动」。实际：前者是改参数（一行）；后者的整段实现随 C3 的桥接被**删除**，不存在「改成传 `_symbol`」这一步。

### C5 P1-1 表格里 `30, 1500` 一行的归因不精确
原文写：`30, 1500` → 「1500 越界整行丢弃，但 `30` 这类行会 → 港股 `00030`」。
实测更正：
- 裸 `30`（无第二个数字）**没有数字支撑**，修复前后都会被跳过，**从来不会**变成 `00030`；
- 真正会造 `00030` 的是**两个短数字**同时出现，例如 `30, 25`。

原文把两种不同输入压在一格里，导致这条修复项「是否闭环」在报告里无法判定——这正是 C1 残留得以藏身的地方。

### C6 P3 `total_position_pct` 的机制归因不准确
原文写：「`total_position_pct=0` **经 `keep_non_empty` 被丢弃**」。
实测更正：`keep_non_empty` 在 `right` 为 falsy 时返回的正是 `right` 本身（`return left if left else right`），**并不会把 0 变成 `None`**。真正的缺口是：在 reducer 层「缺省」与「合法的 0」没有区分手段。
修复后四态实测（走完整 E2E 落库，读回报告头部）：

| 入参 | 报告头部 |
|---|---|
| `total_position_pct: 0` | `…｜当前总仓位：0%｜…` ✅ 保留真 0 |
| `total_position_pct: ""` | 不显示（视为未提供）✅ |
| `total_position_pct: null` | 不显示 ✅ |
| 不传该字段 | 不显示 ✅ |

### C7 原文 P3 说「这里没有（冲突告警）」已不成立
原文 P3 条目：`market_type="us"` + A 股代码 `600519` → 「workflows 主链路有 warning，**这里没有**」。修复后 `stock_sentiment.py:57-76` 已有显式冲突告警。这不是原文的错（写报告时确实没有），但**引用该条时不应再作为未修项**。

### C8「测试面全绿」需要限定范围
原文写：「新增 8 文件 **115 passed**、历史契约 8 文件 **87 passed**、前端 vitest **13 passed**、`vue-tsc` exit 0 —— **测试面全绿**」。
前半句的计数是对的（我本轮跑出的是同一批文件的 **178 passed**，因为补了 3 例），但「测试面全绿」这个总结句会让人以为**全仓无失败**。实测存量基线失败 **18 例**：

### C9 P1-2 修法与最终实现不一致，按原文实施会做出多余的分层
原文建议「区分『真实非 A 股持仓』与『弱形态兜底命中的可疑标的』」。最终实现**没有引入这个区分**，而是整体删除了 `market_type != "cn"` 的整包降级。
